# V1 Prompt Templates

使用 claude-code-setup-v1 開發時的常用 prompt 模板。`<!-- ... -->` 為每次使用時替換的佔位符。

**共用結尾（視需要附加到任何 prompt 後）：**

> 若有任何問題請與我討論，若有任何你覺得需要修正的地方請提出來並且給予修正建議，我們再來決定要如何進行優化，使這個正式產品可以達到業界最佳實踐。

## Planning

### 計畫確認

```
我認可你的計劃，但務必遵照 CLAUDE.md、maintaining-spec-md skill 的流程進行，
以維持 TDD 開發的品質，請根據 CLAUDE.md 補充你的計劃。
```

### 選項選擇

```
請詳細跟我說明這些選項，以及你的建議，
幫助我做出符合業界最佳實踐的選擇。
```

我的需求：

請先看看我 poc 專案的代碼，我們再來決定要如何進行優化、重構，

## Code Review

### code-simplifier 審查

```
請幫我用 code-simplifier 分析 <!-- Module --> 模組代碼。

你覺得如何？若有問題請提出需要修正的地方，並且提供修正建議，
我們再來決定要如何進行優化、重構。

審查重點：
- 過度設計
- 結構不良
- 冗餘/重複/未使用的代碼
- 邏輯問題、hard coding
- 風格不統一
- class / function / 檔名命名易混淆
- 不符合業界最佳實踐
```

### 移除向後兼容

```
請檢視我專案的代碼，並移除我代碼中所有向後兼容的部分（代碼、文檔、測試），
以維持專案代碼的簡潔，尤其是 <!-- Module --> 的部分。
```

## Testing

### 優化測試

```
請仔細一個一個的審查我所有的單元、整合、e2e 測試，並與我討論：

1. 單元測試的架構是否按照實際代碼的架構 mapping？
2. conftest 的 fixture 是否都有被正確使用？ 還是有些測試明明可以用沒用，卻又寫自己的 fixture？
3. 測試的 docstring、註釋是否精確？邏輯與實際代碼有無衝突或錯誤？
4. 有沒有測字串是否出現特定詞這種無意義測試需要刪除？
5. 有沒有其他毫無意義、不需要存在的測試？
```

## Documentation

### 優化文檔

```
請檢視我專案的代碼，並且優化 README.md 以及 docs/ 的內容。
目前這些檔案的內容許多都資訊過時、內容錯誤且雜亂，不符合業界最佳實踐。

請按照 .claude/rules/documentation-style.md 的規範優化我的文檔。
若你覺得有需要都可以建立新的 .md 檔，
並將其放在 docs/ 以維持文檔架構及內容的整潔。
```
